# Dynamics 365 Integration

This folder holds the installable Dynamics 365 / Dataverse CRM extension for
openCloser.

Product-level onboarding and admin-app flow:
[Client Onboarding and Admin App](../../docs/architecture/openCloser_Client_Onboarding_and_Admin_App.md).

Release and future repo split:
[Release and Repository Strategy](../../docs/architecture/openCloser_Release_and_Repo_Strategy.md).

The integration follows the repo constitution:

- Dynamics remains the operator control plane.
- openCloser owns eligibility, call execution, persona handling, idempotency,
  and CRM write-back.
- CRM command code only collects record context and triggers openCloser.
- No custom openCloser product UI is introduced for the MVP.

## Target Components

- Lead command bar button: `AI Call Lead`
- Campaign command bar button: `Run openCloser Campaign`
- Dataverse environment variables for openCloser endpoint and run behavior
- Optional Power Automate flow or custom connector trigger
- Managed solution package for customer installs

## Directory Layout

```text
integrations/dynamics365/
├── docs/                         # install, configuration, and API contract notes
├── webresources/                 # command bar JavaScript source
├── flows/                        # Power Automate flow design notes/placeholders
├── solution/                     # unpacked/packed Power Platform solution area
│   ├── src/                      # unpacked solution source, generated by pac
│   ├── managed/                  # generated managed solution zips
│   └── unmanaged/                # generated unmanaged solution zips
├── config/                       # deployment-settings templates
└── scripts/                      # pack/import/config helper scripts
```

## Current Scaffold Status

This is a source scaffold, not yet a complete importable managed solution. The
next implementation step is to initialize the Power Platform solution source
with `pac`, add the command bar components and environment variables, and then
pack the managed solution zip.

The scaffold stays here while the `/v1` runtime trigger contract settles. Before
external client release, move this folder into `openCloser-dynamics365` so the
managed solution and AppSource package can release independently.

See [docs/install.md](docs/install.md) for the intended install path.
